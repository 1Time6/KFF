| 词 | 含义 | 反例（不得这样用） |

> **⚠ 两机数据禁止混合统计。** 本文件全部结果 = **Machine A**。
> 台式机结果**必须单独标记 Machine B**，且**不得**与 Machine A 的数字合并求平均、合并成功率或互相校准。

**负载单位定义**：`负载 = 自旋进程数 ÷ 逻辑核数`（本机 8 逻辑核）。
8 = 1.0×，12 = 1.5×，16 = 2.0×，20 = 2.5×，24 = 3.0×。
自旋进程 = `node -e "const end=Date.now()+5400000;while(Date.now()<end){Math.sqrt(Math.random());}"`（busy-loop）。

**预算算术**（`process-tree.ts` / `guardian.ts` 当前实现）：

```
settleReserve = max(1, min(floor(force/5), 1000))
deadlineMs    = max(1, force − settleReserve)
killReserve   = max(1, min(floor(deadlineMs/3), 1500))
enumDeadline  = deadlineMs − killReserve
```

| force | settleReserve | deadlineMs | enumDeadline | killReserve | 谁在约束 |
|---|---|---|---|---|---|
| **5000**（集成用例测试预算） | 1000 | **4000** | **2667** | **1333** | `deadlineMs/3`（**不是**上限） |
| **10000**（生产默认） | 1000 | **9000** | **7500** | **1500** | `KILL_RESERVE_MAX_MS` 上限 |

**`force` 语义（重要，曾被我理解错并已更正）**：`force` 是**终止阶段**的预算，**不是**初始等待时间。
`forcedUntil = Date.now() + policy.force` 只在**宽限期失败之后**才设置。`waitForTerminal` 在子进程 exit 到达时**立即返回**，
因此在**顺利路径上提高 `force` 不增加任何墙钟时间**；预算只在 kill/枚举被饿死时才起作用。
—— 这条不是推理：row 0 在 force=10000 下 79.19s 通过，直接证伪了"force=10000 会多花 5 秒"的担心。

### 4.5 §8 裁定（**已定，不得重开**）

| 项 | 裁定 |
|---|---|
| **下一步** | **G + H 并行** |
| **G** | **非侵入式记录** —— 用例里包一层 controller，每次调用连同抛出的 `AppError.code` 记进数组，失败时 dump。抓**真实发生的那一次**，不改控制流 |
| **H** | **控制端故障注入** —— 让 controller 可按指令抛 `LEASE_STALE` / 返回非 `READY` / 触发 mid-flush redaction。把三条路径**逐个钉死**，且**确定性** |
| **J** | **仅在 G 或 H 已经定位到根因之后**才做（新增 flush 确定性单测） |
| **I** | **仅当证据明确指向 heartbeat / lease freshness 时**才做（测试内 heartbeat 循环）。**当前证据不指向它** —— 朴素 TTL 假设已被证伪，且观测 1 的分支特征（恰好 2 条租约、无 redaction）并未指向续租 |
| 🚫 **K 禁止** | **禁止**通过调整租约 TTL 或放宽测试来"解决"。TTL 是陈旧度上界，触碰它等于降低安全门槛 |
| 🚫 **一并禁止** | 不得通过以下任何手段把测试人为改绿：**延长 TTL / 放宽 assertion / 修改安全状态机 / 增加无依据 retry / 修改 test force** |

**G 与 H 互补**：G 抓**真实发生的那一次**（不改控制流），H 把三条路径**逐个钉死**。
只做 J 会得到一个"代码是对的、但集成里为什么返回 false 仍不知道"的结论。

### 4.6 §8 与 §7 的耦合（排期必读）

§8 的复现依赖"用例至少跑到 flush 断言"。而 §7 表明 **3.0× 下用例连终止断言都过不去**，
所以 §8 的可复现负载窗口是 **1.5×–2.0×**，**比 §7 更窄**。
**若先按 §7 的某个选项调整 kill 份额，终止断言的通过区间会改变，§8 的复现窗口需重新标定。**
