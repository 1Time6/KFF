## 3. 新发现 F1：终止记录竞态（guardian.ts）

### 3.1 机制（代码路径，PROVEN）

- `guardian.ts` `settle()` 是**同步**执行 decide 回调；`child.once('exit', () => settleTerminal())`。
- watchdog 触发后，`terminate()` 先 `await terminateProcessTree(...)`（异步：枚举 powershell →
  taskkill → 探测），**完成后**才把结果赋给 `forcedTermination`。
- taskkill 杀死子进程的那一刻，`exit` 事件同步进入 `settleTerminal` → `recordNoProgress()`，
  此时 `forcedTermination` 仍为 `undefined` → `terminationFact()` 落盘**回退事实**：
  `{process_tree:UNKNOWN, tool:SKIPPED, root:DEAD(现场探测), descendants:UNKNOWN, sampled:0,
  enumeration:UNAVAILABLE, elapsed_ms:0}`。
- `terminateProcessTree` 随后完成（其真实 DEAD/LISTED 判决）但**已没有机会写入记录**。

### 3.2 观测（Machine B，OBSERVED）

- 矩阵 1.0×–3.0× 全部 6 个 stall 用例实例在 `browser-message.test.ts:298` / `:384` 的
  `termination` 断言处失败，diff 全部相同：期望 `descendants=DEAD / enumeration=LISTED /
  process_tree=DEAD`，实际 `UNKNOWN / UNAVAILABLE / UNKNOWN`，`tool=SKIPPED`、`elapsed_ms=0`。
- row 40 落盘记录：`forced=true, grace_ms=1000, waited_ms=6788`，root 现场探测 `DEAD`
  —— kill 已发生，但记录里没有 termination 结果。
- 时序闭合（PROVEN）：§2 探针 3.0× 枚举 4–5 s、kill ~3 s；子进程在 taskkill 阶段死亡，
  exit 事件先于 `terminateProcessTree` 返回。
- 0× 行 12/12 通过：空载枚举 < 1 s，赋值先于 exit 事件 → 竞态方向由枚举耗时决定。

### 3.3 BASE 对照（代码级，非“结构性不可得”）

`git show 752042b:apps/agent/src/guardian.ts`：BASE 没有 watchdog / terminate / no-progress
记录机制，exit 处理器只读 closure 证据。因此该竞态窗口是**本工作区新增机制**（P1-04 的异步
终止 + `recordNoProgress`）内的时序窗口；BASE 无可比路径。此说法只涉及终止记录，**不**涉及
§8 flush 的“是否回归”问题（后者仍结构性不可判定）。
