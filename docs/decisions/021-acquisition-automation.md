# ADR-021：主动获客与自动执行

日期：2026-09-12。用户要求补齐评论采集、主动获客和自动私信，并明确“还没有来源，先完成系统并列出接入条件”。本决定扩展 ADR-020 的接待范围；不把之前接待链路的本地验收当成本轮采集或真实平台验收。

新增 `/acquisition` 工作台：Facebook / Instagram 来源配置、关键词和排除词、评论/关键词/主页/话题策略、定时分页采集、去重线索池、规则评分、状态管理、一次互动和自动规则。沿用 collection checkpoints 与原有 Task → Approval → Worker → Agent → guardian → Receipt，不另造发送队列。

来源分为本地合成、自有评论 Meta API、外部数据服务。全域搜索与竞品采集由外部服务返回规范化结果，KFF 不宣称获得平台全站索引，也不把未接入的来源展示为成功。Meta 原生适配器只接受本账号自有内容评论；需要真实账号验明字段、权限及 API 版本。

评论触发私信和公开回复使用冻结目标的一次任务。已有客户主动 Messenger 私信继续使用会话和服务窗口。真实动作走 CONTROLLED_PILOT，逐任务批准、核实账号与凭据版本、检查预算/停止/原动作结果；本轮不自动升级 PRODUCTION。合成环境可完整自动执行。商用持续发送需要单独真实验收及能力放行。

用户尚无数据源和真实凭据，因此本轮交付标准是本地系统可运行、来源合同可对接、缺配置明确失败、真实接入条件可执行。详细配置见 [接入说明](../api/acquisition.md)，验证结论见 [当前完成度](../acquisition-readiness.md)。
