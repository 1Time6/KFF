# AdsPower 真实会话收件

0.1.15 增加 `RECENT_ACCEPTED` 模式，0.1.16 补充标题显示后等待主页链接完成加载的有界核验：管理员可选择从中文“全部”聊天列表核实最多 1–3 个近期可见会话，合计不超过原消息页上限。固定会话模式继续保留，两者互斥；更改配置前必须暂停并等待原任务关闭。该模式核对列表中的加密会话链接、会话标题的数字个人主页链接，并沿用逐条来信头像核验。不会从消息摘要猜测身份，也不会点击接受消息请求。

发现结果记录已核实会话、跳过原因、未识别行数及窗口是否受限，保存在原审计事件中；仍使用原队列、检查点和 Inbox，没有新增客户数据库。只支持当前可见文字窗口，不承诺所有会话或完整历史；会话类型保留 `UNVERIFIED`，不生成自动发送权限。没有明确空状态时不会宣称“没有消息”。Messenger 要求创建或输入 PIN 时返回 `MESSENGER_SETUP_REQUIRED` 并暂停，由本人在原 AdsPower 窗口完成。

0.1.51 修复已观察到的目录占位名称加载顺序：目录先显示“Facebook 用户”，同一加密会话随后出现真实名称与数字个人主页链接。该占位名称不作为人的身份；读取器只在原会话地址和唯一数字标题链接均一致时采用标题的已加载姓名，再逐条核对来信头像的数字主页。仍停留在占位名称、标题缺少或有多个链接、已知真实姓名冲突、来信头像指向不同 ID 时拒绝读取。此处理不查询历史姓名或猜测个人 ID，也不放宽原读取时间、消息上限或发送权限。

同版本修正已读头像在跨日后带完整日期的显示形式，仍只排除正文外、明确标为已读的 14×14 头像；正文内图片及无法识别的媒体继续停止读取。验证范围和现场结果见 [当前目标进展](../tasks/goal-resume-20260913.md)。以下记录保留其原版本范围。

`facebook.inbox.read.browser` 使用 `facebook-inbox-browser-v1` 和固定模板 `facebook-inbox-dom-v1`。适用于已绑定 AdsPower、已登录的 Facebook 个人账号。0.1.4 的范围是中文界面上一个已接受的加密会话中已渲染的双方文字消息，不覆盖附件、群聊接待、历史翻页或所有陌生消息。

管理员在 Inbox 的“浏览器收件”中选择环境并固定会话 ID、发送者个人主页 ID 和显示名称。配置存入原监控绑定，随后需登记当前代码证据，并为本机控制端、Agent 开启 `KFF_ENABLE_BROWSER_INBOX=true`。发送总开关可以保持关闭。普通任务接口不能自行添加收件范围。

每轮仍由原 Worker 创建任务、许可和资源租约，由安装的 Agent/guardian 打开绑定环境。执行器先核对自己的个人主页身份，再打开指定会话；客户来信逐条滚动到头像并通过菜单核对个人主页，己方文字需要明确的“你”标签且没有发送者头像菜单。正文外、明确标为已读的 14 像素头像不作为附件。读取后再次核对自己的身份。小窗口先滚动到个人主页标题，等待好友标签显示后继续身份核验。消息页、入库和检查点由原回执事务共同提交；下一轮需要取得上一轮的关闭证明。

当前模板不推断完整日期。页面只显示时间或相对日期时，`occurred_at` 和数据库 `client_sent_at` 为 `null`，`displayed_time` 保留页面文字。Inbox 分别标注平台显示时间与 KFF 收件时间。消息 ID 仅用于去重，不用于解码或猜测发送时间；后续显示名称或时间标签变化不会重新建档，正文、消息归属等变化仍报冲突。

Messenger 可在头像核验时补载此前未渲染的消息。读取器最多复核三轮，只允许在页上限内增加消息，原有行的内容、方向、发送者、时间标签及相对顺序必须不变；新增来信仍逐条核验发送者。删除、编辑、重排、重复 ID、不支持的字段或持续加载均停止本轮，不提交半页结果。

页面没有足够的一对一类型证据时保留 `thread_kind=UNVERIFIED`，并只建立可查看的人工接待会话，不创建官方接口窗口、PSID 或真实自动回复权限。执行器不接受陌生消息请求、不填写回复、不点击发送或通话。一次读取中出现不支持的消息形态、错误发送者、字段冲突或超过页上限，会停止该轮并保留原因。

真实能力通过新增的只读许可范围启用，沿用原品牌权限及审计。第 30 条迁移仅扩展许可约束，不改写既有业务数据。迁移生成流程参考 [Supabase 数据库迁移文档](https://supabase.com/docs/guides/deployment/database-migrations)。
