# KFF 自有收件与客户接口

决策：ADR-017。KFF 独立拥有客户、会话、消息和后续订单主数据。本页是已实现的站内入站协议，不代表人工回复、Facebook 消息或支付已完成。

## 品牌工作台

以下接口要求有效的运营登录，品牌来自服务端授权上下文；写入必须同源，查看者不能写入。

| 接口 | 行为 |
| --- | --- |
| `GET /api/inbox` | 品牌内最近 200 个会话、100 个入口；分别返回客户人数、会话数、消息数 |
| `POST /api/site-channels` | 管理员创建自有入口及独立 `site/inbox` 账号；不生成 Facebook 能力 |
| `POST /api/site-channels/:id/controls` | 管理员按 `expected_version` 暂停/恢复，需请求 ID 和原因 |
| `GET /api/conversations/:id?after=0&limit=50` | 品牌会话与消息；按接收序号递增，`limit` 最大 100 |
| `GET /api/customers` | 最近 200 位客户及本品牌可分配成员 ID/角色 |
| `GET /api/customers/:id` | 客户、身份、会话、最近 200 条时间线；来源未知明确保留 |
| `POST /api/customers/:id` | 按客户版本修改称呼、负责人、阶段及依据 |
| `POST /api/customers/:id/notes` | 写入不可变跟进备注，请求重放不重复写入 |

入口创建必须显式提供：`request_id`、名称、是否合成测试、访客会话有效小时数（1–720）、每次咨询的客服回复窗口小时数（1–168）、每分钟新会话上限（1–1000）和入口消息上限（1–10000）。每名访客另有限额 20 条/分钟。参数保存后固定；本阶段控制接口只改变启停状态，新规则使用新入口。

负责人只能是当前品牌有处理权限的成员。客户阶段 `OPTED_OUT` 会在同一事务中退出已绑定的联系身份；改回其他阶段不恢复联系资格。成交/交付阶段目前是人工标记，不能作为已核实收入或交付凭证。

## 自有访客端

访客页面为 `/chat/:channelId`。以下接口不使用运营登录；客户端不得选择品牌、客户、访客 ID、联系依据或消息状态。

| 接口 | 鉴权与行为 |
| --- | --- |
| `GET /api/public/chat/:id` | 仅公开入口名称、启停、测试类型及会话/窗口时长 |
| `GET /api/public/chat/:id/sessions` | 返回当前浏览器在此入口的有效会话状态，不返回令牌 |
| `POST /api/public/chat/:id/sessions` | 同源、空 JSON；复用有效会话，或受持久限额约束签发新会话 |
| `GET /api/public/chat/:id/messages` | Cookie 鉴权；只读此访客的历史，支持 `after/limit` |
| `POST /api/public/chat/:id/messages` | Cookie 与同源鉴权；同一事务持久收件后返回 `STORED` |
| `POST /api/public/chat/:id/end` | 同源、空 JSON；撤销此会话并清除 Cookie，保留已存消息 |

服务端生成随机访客 ID 和 256 位随机令牌。数据库仅保存令牌 SHA-256；令牌仅通过 `HttpOnly; SameSite=Strict` Cookie 传递，路径限定在本入口 API，HTTPS 使用 `Secure`。不写入 URL、本地存储、审计正文或 API JSON。匿名新会话不会按姓名自动取回旧客户，结束/过期后的新身份保持分离。

消息载荷为 `client_message_id`（UUID）、`body`（去除首尾空白后 1–5000 字）、`display_name`（可空，最长 80 字）及 `client_sent_at`（可空 UTC 时间）。完整规范化载荷的摘要保存在共用 `inbound_events`，正文、提交称呼和客户自报时间保存在消息记录中；不保存 Cookie 或其他任意请求字段。HTTP 原始消息体上限 32 KiB。

事件唯一键为入口 ID / 服务端访客 ID / 客户端消息 ID。原请求重放返回同一消息；改变载荷返回 `IDEMPOTENCY_CONFLICT`。确认丢失时，访客页面保留同一消息载荷与 ID供重试，确认前禁止改文重发。仅开始会话不会建客户；首条实际入站消息才原子建立客户、渠道身份、会话、消息、服务依据及时间线。

所有记录先在同一数据库事务提交再确认。会话序号按服务器接收顺序递增；客户自报时间只是保留字段，不能回拨顺序或服务窗口。旧消息重放不延长窗口、不扣新配额。数据库故障或提交前进程终止会一起回滚记录及配额；提交后确认丢失不会制造第二条记录。

暂停入口阻止新会话和新消息，但仍允许有效访客读取自己的历史、确认已存原消息。过期/撤销会话不能读历史或新提交。新入站咨询不会撤销之前的退出状态；它生成的新依据仍被共同联系资格检查拒绝，直到取得新的明确同意。

## 证据与当前边界

同库持久事件表扩展为 `agent` / `site_chat` 来源；原 Agent 事件仍要求命令和 Agent 引用。新增表启用品牌 RLS，复合外键固定身份、会话和消息的关联。消息、客户事件与当前身份不可直接改写。已应用迁移保留，后续身份纠错通过专门任务实现。

本阶段 `outbound_available=false`、`execution_authorized=false`。没有发送端点或自动回复旁路，TASK-080/081 将把人工回复、控制权和提交资格接入共同执行器。公网部署、跨域嵌入、外部平台 Webhook、完整保留/删除策略、渠道规则更新、超过当前列表上限的搜索分页及完整客户合并不在本次验收范围。

页面与 API 只记录当前已实现的状态，不把入站消息确认当作出站送达、客户成交或真实 Facebook 验证。
