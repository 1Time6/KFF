# 真实浏览器人工回复

当前范围是已绑定 AdsPower 个人账号、已读取的指定 Messenger 会话、单条人工回复或 WhatsApp 邀请。使用原 Task、Worker、Agent、guardian、Message 和 Referral，不建立独立发送队列。

## 工作台步骤

1. 在 Inbox 的 Facebook 接待配置中选择个人账号和原绑定环境，保存「AdsPower 人工回复」。真实个人账号目前仅支持人工接待。
2. 在当前客户会话中展开「登记本次客户同意」，记录实际发生的同意时间、依据及最多 60 分钟的本次有效期。该入口不恢复已退出的客户，也不会修改原始来信或补造平台时间。
3. 在人工回复中选择同意记录，输入正文或选择账号的 WhatsApp 话术，再准备回复任务。
4. 在原任务工作台审核确定的账号、会话、客户和正文，为同一任务登记一次动作许可，再按原流程排队。执行前再次核对同意、来信、人工处理权、账号状态、目的地版本和停止控制。

新接口 `POST /api/conversations/:id/browser-consent` 沿用原会话鉴权与 CSRF；管理员填写 `request_id`、`expected_version`、`consented_at`、`expires_at`、`evidence_note` 和 `confirmation=CUSTOMER_CONFIRMED_THIS_CONTACT`。记录委托原 `grantContactPermission`，绑定当前会话的最新真实来信。准备接口继续使用 `/pilot-reply`，额外传入该 `contact_permission_id`。

## 执行与结果

`facebook-browser-messenger-v1` 使用固定模板，执行前核对登录账号、消息头像对应的客户 ID、会话 URL、最新消息 ID 和正文摘要。已有草稿、会话发生变化、身份不明或按钮被遮挡时停止。提交意图由原控制端登记，发送入口至多触发一次。

成功必须取得唯一的新消息 ID、相同正文以及页面明确的发送状态，再复核自己的账号。回执绑定账号、会话和对方；结果未知时保留原动作，不重发。原 guardian 的关闭证明仍决定是否释放环境。WhatsApp 邀请回执与客户实际联系、销售确认分别登记。

2026-09-13，用户批准的一条 WhatsApp 邀请已通过原 Agent 提交一次。旧解析器未识别页面“5分钟前发送”文字，原尝试保留 UNKNOWN_OUTCOME；独立核对同一消息 ID、正文、双方数字身份和关闭证明后，经原裁定入口确认同一动作，回执类型为 human_review，没有重发。用户随后明确回复“WhatsApp已收到”，原 Referral 登记为 CONFIRMED、客户为 HANDOFF_COMPLETE；到达及接手依据是用户确认，未观察 WhatsApp 自动回调。详见 [本轮邀请记录](../whatsapp-test-review.md)。

0.1.4 识别己方明确文字标签和正文外的相对发送状态，并区分 Messenger 已读小头像与附件。当前 125 项合同、21 项自有 DOM/已捕获 HTML 回放以及类型和代码检查通过；20 项相关隔离库集成已覆盖未再修改的控制端入库与队列流程。实际首次发送验证为独立核对后的人工裁定；修复后的即时自动发送回执尚未用第二条真实消息验证。

原收件报告入口现接受指定会话的双向消息批次：与原动作回执的账号、会话、消息 ID 和正文匹配的己方消息只保存观察事件；原 OUTBOUND 不重复创建。其他己方消息保存为 EXTERNAL_OUTBOUND，并进入人工处理；客户新来信更新最新来信位置，旧来信的单次同意不能用于新消息。重复读取去重；身份不匹配或同一 ID 的方向/正文冲突时，整页事务回滚。页面只有时间标签时仍不补造日期或已回复关系。

上述入库行为包含 2 项混合历史集成场景，见 [双向入库测试证据](../evidence/mixed-browser-history.json)。0.1.4 页面读取器也支持指定会话的双方文字：客户消息逐条核对头像对应的个人主页 ID，己方消息需要明确的“你”标签且没有发送者头像菜单。可见范围和完整日期限制不变；Inbox 对裁定产生的己方消息显示记录时间，不把触发来信的平台时间冒充发送时间。

## AdsPower 慢启动恢复

本机曾在 20 秒启动请求超时后才创建浏览器，导致未取得启动确认的 guardian 退出并保留隔离。启动请求现有 60 秒有界等待，状态查询仍为 20 秒；21 秒延迟响应的合同测试确认只发起一次启动请求。

`scripts/recover-adspower-read.ts` 是人工调用的原只读任务恢复工具：检查过期且无提交意图的原收件命令、已退出的 guardian、配对和原锁，核对指定 Profile、浏览器进程启动时间与端点；关闭仍在运行的同一实例，或核验操作者曾观察到的同一实例已经退出。恢复记录明确标为人工观察，并由原 Agent 回传关闭证明。该工具不产生读取成功或发送成功回执，不重新执行旧命令；解除隔离仍使用原控制端入口。未知启动不能仅凭短暂的 Inactive 自动恢复。
