## Facebook 个人账号公开搜索

0.1.7 搜索模板在配置 `max_age_days` 时打开页面的“近期帖子”筛选，并在每轮读取及检查点回放时核对该开关。平台的“近期”不等于指定天数，最终仍按每条原始日期执行 KFF 时效规则。未配置范围的既有监控保持原搜索方式。

搜索条目保留同一公开帖子的原时间链接文字。只有唯一来源链接在悬停前没有残留提示、悬停后出现一个完整日期，且链接和时间标签没有改变时，才采用该日期。重复或冲突链接、隐藏节点、嵌套评论、残留提示都不能提供别的帖子的时间；无法确认时保留相对标签或未知值。所有日期继续保存为 `DISPLAYED_TIME`，不补造时区或精确UTC时间。公开标识、正文和标题也限定在当前帖子自身。

管理员选择真实 Facebook 个人账号及已配置环境，来源为“Facebook 浏览器公开内容”，策略为“关键词搜索”，每个搜索监控只填一个关键词。当前识别可见的公开 Reels，以及个人主页路径下具有数字或 `pfbid` 标识的普通帖子。读取前后都通过 `/me/` 的实际数字身份、自有编辑入口、好友标签和名称核验身份；页面地址和控件可分阶段加载，等待仍有明确上限。

## Facebook 指定公开帖子的评论

在同一来源下选择“评论区”，填写已观察过的普通帖子完整链接，如 `https://www.facebook.com/作者/posts/帖子ID/`。链接须去除查询参数、保留末尾斜线；当前模板不接受 Reel、小组、个人主页或外部跳转链接作为评论目标。关键词用于筛选评论正文，可填写多个。

`facebook-comments-dom-v1` 复用同一代码证据、每页只读许可、身份前后核验及原任务队列。页面必须显示与目标链接匹配的公开帖子，排序固定为“由新到旧”，只读取顶层评论。评论的数字 ID 来自可见时间链接的 `comment_id`，正文来自唯一的可见评论正文区域，原始来源链接保留该参数。数字作者 ID 仅在可见作者链接明确返回时保存，其他字段不推测。回复、头像、输入框、点赞和私信入口不作为正文。

每页检查点固定查询摘要、来源和最后一条评论 ID。已加载但折叠的正文先展开；身份、目标、排序或原检查点发生变化会阻止继续读取。明确显示“还没有任何评论哦”时可记录本次空结果；滚动后暂时没有新记录只表示当前窗口结束。最新排序不代表平台返回全部评论，覆盖范围仍为 `BROWSER_VISIBLE_ONLY`。

重复定时读取保留新的观察记录；同一监控中，评论 ID、正文和来源均未变时只更新线索最近观察时间，不增加线索或撤销已有审核状态。监控按系统真实时间调度，每轮仍受条数和页数上限约束。创建监控默认暂停，“启动持续监控”之后由原 Worker 到期创建查询，“暂停”取消在途查询并保持关闭隔离。程序未运行、浏览器人工占用或平台登录失效时无法保证持续采集。

## 合成评论与共用机制

管理员在 `/acquisition` 选择合成账号，先在环境中心保存浏览器配置，再选择“本地浏览器采集验证”、采集环境和每页上限。保存监控后可扫描一次或持续扫描。界面始终将结果标为合成验证；这种来源不能生成平台互动动作。

监控输入示例中的环境 ID 必须来自同品牌、同账号的已配置环境：

```json
{
  "provider": "LOCAL_BROWSER",
  "browser": {
    "environment_id": "当前账号的环境UUID",
    "template": "fixture-discovery-dom-v1"
  }
}
```

以上是 `discovery` 对象的新增部分，其余平台、关键词、目标和用途字段仍按现有合同填写。监控可设置 `page_size`（1–100，默认50）；`max_records` 和 `max_pages` 限制整个扫描。Web 默认每页25条。配置和身份在创建查询时固定，后续配置变化使原查询停止，不能暗中换账号继续。

每页由 Worker 创建一个 `kff.fixture.discovery.read.browser` 只读任务，保存在原任务队列；`collection_runs.browser_task_id` 用同组织、同品牌外键指向当前页任务。HTTP 采集器不能领取这些查询。Agent 从受管环境的可见 DOM 核对登录账号和操作身份，提取一页字段，确认关闭浏览器后交回内容摘要和页面数据。采集不经过发送边界。

服务端在验证原命令、账号和环境租约后，在接收回执的同一事务内写入原 `collection_pages`、观察版本和去重结果。成功后才推进游标并准备下一页；重传相同回执不会再次入库，修改过的回执被拒绝。原评分、作者退出和线索状态投影继续生效。

停止、监控暂停或查询到期后，未交付页面任务取消；已领取任务通过心跳收到停止信号。晚到的页面只记录丢弃审计，不导入结果。已经确认的读取失败可从原游标恢复；租约丢失或关闭未确认仍沿用原隔离规则，不能自动重新占用环境。

`agent/action-reports` 的请求上限为2 MiB，采集数据仍受每页100条、字段类型和来源校验约束。每页任务固定原查询的 `expires_at`，Agent 将这个期限存入本机命令日志。原始页只在回执尚需重传时暂存；控制端确认入库和关闭后，清除日志与关闭文件中的原文，留下事件ID、回执摘要和原关闭证明摘要。

保留期到达时，本地清理先于控制端心跳执行；控制端断网也不能延期保留。尚未确认的页改为不含原文的 `RETENTION_EXPIRED` 终止回执；重连先查询原命令，若原入库确认丢失且命令已结束，仅补交关闭证明。关闭证明缺失或nonce不符仍阻止新接单，清理不解除隔离。查询在读取或关闭期间到期，guardian不会把原始页写入关闭文件。

清理意图先持久化，再原子替换关闭文件，中途退出在下次运行恢复；压缩文件保留原证明哈希，控制端的重复关闭确认继续幂等。旧合成任务缺少查询期限时采用命令期限；旧日志缺少任何期限时立即保守清理，不能在重启时重新延长保留期。Agent退出期间不运行定时清理，启动后的首次本地维护执行清理。这一范围只覆盖Agent回执与关闭日志，不代表浏览器缓存或外部备份的清理。升级后需要保留支持 `kff.guardian-closure-compact.v1` 的恢复读取器，不能回退成把压缩证明当作完整原文的旧版本。

测试分别记录数据库合同回执和真实本机 Chromium DOM 读取，二者都不代表平台账号验收。实网验收仍需要可用的原代理、已核对的平台登录身份和实际可见页面。
