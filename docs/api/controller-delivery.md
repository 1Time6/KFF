# Windows 完整控制端交付

此包包含生产 Web、Worker、配套 Agent、Node、锁定的依赖和 PostgreSQL 17 程序。AdsPower 及各自账号登录、代理仍使用本人配置，不随包提供。适用于 Windows x64。包内没有运行数据库、密码、配对或浏览器登录数据。

## 新电脑首次安装

1. 核对压缩包 SHA-256，解压到一个新的英文路径，例如 `C:\KFF\0.1.26`。保留完整目录结构。暂不支持带中文的数据库目录路径。
2. 在目录内运行 `controller.cmd verify`，然后运行 `controller.cmd setup`。无需先安装 Node、pnpm 或 PostgreSQL。初始化只创建本机操作者、品牌和 Agent，不生成测试客户或合成账号。
3. 打开新生成的 `.kff\本地登录.txt`，使用其中的本机账号密码。不要分享此文件。
4. 运行 `controller.cmd start`，打开 `http://127.0.0.1:3000` 登录；运行 `controller.cmd status` 查看 Web、Worker、Agent 状态。
5. 启动已安装的 AdsPower，在工作台配置本机 Key、选择现有 Profile 并核对账号身份。包不会替换代理、登录或 PIN，也不会自动创建采集监控或发送消息。
6. 正常退出用 `controller.cmd stop`。组件已退出时可用 `controller.cmd recover`，沿原回执和关闭证明恢复。

默认使用本机端口 3000 和 55432；端口被占用时 setup 会在创建数据前拒绝。隔离安装测试可显式使用 `controller.cmd setup --database-port 55439`，Web 仍固定在 3000。

## 数据与版本

每个安装目录的 `.kff` 保存自己的数据库、登录和原执行记录。重复 setup 一律拒绝，不覆盖已有数据。初始化失败后保留原目录和日志，不自动删除重建。包文件逐项校验；仅 `.kff` 数据目录和 Next 的运行缓存允许变化。摘要不是发布者数字签名，应从可信来源取得包和校验文件。

## 从旧版完整控制端升级

1. 在旧版暂停采集和 Inbox 监控，关闭自动发送，等已接单任务和浏览器关闭回执全部完成，再运行旧目录的 `controller.cmd stop`。确认状态为 `STOPPED`。
2. 将新包解压到另一个新的英文目录。新目录不能已有 `.kff`，不要运行 setup，也不要覆盖旧程序。
3. 在新目录运行 `controller.cmd upgrade --from C:\KFF\0.1.23`，把示例路径换成实际旧安装目录。默认保留原数据库端口；独立验收可附加 `--database-port 55440`。只支持此格式的旧版完整包、本机 PostgreSQL 17 主库和严格更新的版本号；开发目录不适用。
4. 命令会校验两份程序包，锁定正常启动入口，把已停止的数据复制到新目录并逐项校验，只在副本上迁移。登录账号、配对和原记录继续使用；已启用能力只更新对应代码证据，发送保持关闭。成功记录保存在新目录 `.kff\upgrades`。
5. 成功后运行新目录的 `controller.cmd start`，使用原账号密码登录，核对业务记录。新旧版本不能同时运行。旧目录完整保留为升级前的回退点。

如果升级失败，保留日志和新目录，`.kff\upgrade-in-progress.json` 会阻止启动未完成的副本。先查明失败原因，不删除标记强行启动。确认新目录的进程和数据库均已停止后，仍可使用未被写入的旧目录。

旧目录只代表升级前的数据。新版本一旦产生新客户、消息或发送记录，回退必须保留并核对这些新记录，不能直接用旧目录或旧备份替换。另一台真正干净电脑和整机断电恢复需要分别验收，本机隔离目录的成功不能代替它们。

构建命令：先完成当前生产 build 和 Agent 包，再运行 `node scripts/package-controller.mjs --agent-release <当前已验证Agent目录>`。构建只复制当前锁定依赖，不在线安装程序或下载账号数据。
