# KFF 独立商品与订单合同

范围依据：ADR-017、TASK-090/093。客户、会话、商品、订单全部使用 KFF 自有 ID 和品牌主数据；没有接入 EasternWisdom、Pearl 或外部订单账本。

## 接口与操作

所有接口要求运营登录，品牌由服务端授权上下文决定。写请求检查同源；查看者只读。商品管理需要品牌管理员，订单报价、确认和取消允许操作员。

| 接口 | 行为 |
| --- | --- |
| `GET /api/commerce` | 当前品牌最近 200 个商品、订单和客户，以及币种精度登记 |
| `POST /api/products` | 登记 SKU、名称、价格、币种、精度依据、交付范围与条款，初始为草稿 |
| `GET /api/products/:id` | 读取当前商品及全部历史版本 |
| `POST /api/products/:id/versions` | 按当前版本保存新版本，SKU 固定，新版本重新成为草稿 |
| `POST /api/products/:id/controls` | 按版本启用或停用，必须填写依据；控制保留审计 |
| `POST /api/order-previews` | 为一个已有客户预览 1–50 项明确商品和数量，可关联该客户的会话 |
| `POST /api/orders` | 确认预览摘要、精确总额与币种，创建一笔待核实订单 |
| `GET /api/orders/:id` | 读取固定商品/价格/交付/条款快照及订单事件 |
| `POST /api/orders/:id/cancel` | 按版本取消没有在途支付、尚未核实收款的订单，原因永久记录 |

工作台在 `/orders`。客户档案可跳转创建订单及已有订单；订单详情可回到客户和有依据的来源会话。不同客户的会话不能借用。

## 金额、版本与确认

单价使用最小单位整数字符串，0–999999999999999；数量使用 1–1000 的整数。计算使用 BigInt，总额上限 999999999999999999，JSON 和快照仍保持字符串。界面按显式小数位插入小数点，不通过浮点数重新计算。

每品牌每币种登记一次精度（0–6 位）及来源。后续商品沿用已有来源；精度冲突直接拒绝。一笔订单只使用同一币种和精度；当前金额是明确报价项目之和，适用的运费或税费须列入明确项目，本阶段没有自动税率、运费、库存或折扣引擎。

商品版本永久保存名称、单价、币种、交付范围与条款。管理员明确启用之后才可被报价；变价保存新草稿会使旧的未确认预览失效。停用/再次启用也递增状态版本，不能复用旧状态下的预览。

预览固定客户版本、可选来源会话、商品版本、数量及项目/总额，有效 15 分钟。确认时在数据库事务内锁定商品和客户，再用当前数据库时间核对预览期限；等待锁期间到期仍拒绝。客户有新消息或档案改动时需重新预览。预览本身不可修改，使用按预览 ID 划分的事务锁协调唯一消费者，不给予预览表 UPDATE 权限。

相同确认请求重放返回原订单；更改请求内容报冲突。一个预览只能生成一笔订单，不同请求 ID 再确认同一预览返回 `PREVIEW_ALREADY_CONFIRMED`。订单快照不随后续商品或客户修改而改变，取消也不会删除或回写金额。

消息收件使用原持久事件内核；商品/订单使用同一数据库事务、租户授权、RLS 和审计基础。这里没有平台提交或消息发送旁路。

## 状态与后续边界

订单状态为 `OPEN` / `CANCELED`。支付初始为 `UNVERIFIED`，只有服务器核实并原子保存 Stripe 付款凭据后才变为 `VERIFIED_TEST_PAID` 或 `VERIFIED_PAID`。API 拒绝客户端提供“已支付”；数据库要求存在与订单、金额、币种和模式匹配的不可变付款凭据。客户成交阶段、订单创建、成功页均不产生已核实收入。

用户已指定第一阶段使用 Stripe。订单详情返回实际连接状态 `payments_connected`、付款收入标识 `verified_revenue` 和取消许可 `can_cancel`；测试付款不会计入真实收入。有在途或结果未知的支付请求时禁止取消或创建第二笔支付，只有核实原会话已过期或明确失败后才允许再次操作。详情见 [Stripe 支付 API](stripe-payments.md)。

当前只支持运营人员为已确认订单创建托管付款链接。实际 Stripe 测试账号联调、退款、交付、访客自主下单和完整归因尚未验收，不计完整 E2-MIN/G3 通过。

页面验证中已检查 HTML `pattern` 的当前 `v` 模式，SKU 的字面连字符作了转义；依据见 [MDN：pattern 属性](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/pattern)。
