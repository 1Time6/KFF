# Inbox 公开互动来源核对

0.1.18 在原 `GET /api/conversations/:id/reception` 返回 `public_interactions`，由接待页面展示。无需新表、新客户库或新增写入接口。

只针对真实 Facebook 浏览器会话。系统从原来信及浏览器来源记录核对数字主页 ID，再查找同一经营账号对该主页身份的公开评论回复。显示名称不用于匹配。来源必须是 `facebook.comment.reply.browser` 的原任务，动作已 `VERIFIED_SUCCEEDED`，回执对象与经营账号一致，且该动作所有命令已关闭。待审核、提交中、失败、未知结果及未关闭的动作不会列为已核实互动。

页面最多展示最近 20 条记录，包含原评论、原回复、两者链接及原执行记录。内容来自原不可变任务快照和已核实回执，不使用后续变化的采集文本替代当时来源。查询沿用品牌权限和原账号隔离。

“同一主页身份”只说明可以核对同一对象的历史，不证明本次咨询由这条评论带来，更不证明成交。页面分别显示回复核实时间和 KFF 首次收到该会话来信的时间；后者可能是历史消息首次被采集的时间，不冒充平台发信时间。

此查询不会合并客户、创建 Messenger 联系人、生成发送许可、更新线索状态或修改 WhatsApp 移交记录。对实际新线索的来源核对仍需受控评论、具体获准回复、新来信和销售接手的现场证据。

新增两项隔离测试覆盖：独立来信与核实回复的关联，回执和关闭条件，同名不同身份、跨账号和跨品牌隔离，以及不新增接待权限。实机原测试会话应显示 0 条匹配；正向界面用明确标注的本地响应夹具验证，不写入业务数据库。
