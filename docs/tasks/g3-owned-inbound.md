# TASK-078/079/087：自有站内收件与客户基础

基线 `1f1910b`。用户独立主数据决定见 ADR-017。按规划 7.3、8.3、TASK-078/079/087 与 ACC-01/10/20/55/72，先实现 KFF 自有收件入口、品牌身份、客户与会话。

本次允许修改：公共输入合同、数据库新增迁移、业务服务、API、收件箱/客户/访客页面、对应测试、实施与证据文档。原规划、其他项目及真实 Facebook 配置不变。

收件采用品牌管理员创建的站内渠道、服务端签发的访客会话、同源写入与持久限额。一个访客身份只在一个渠道内有效。主动消息、入站事件、会话顺序、客户建档和限定客服用途依据在同一事务提交，重放返回原记录；同一消息 ID 不可替换正文。身份不因同名合并。来源未知时明确保留未知。

本次收件工作台先提供读取与客户维护。发送、接管、AI 与订单后续继续实现，不为发送新建旁路执行器；不会把本次收件检查等同完整 TASK-080/081/082/092 通过。

验证覆盖跨品牌与跨访客、重复/乱序、并发、存储回滚、会话过期、渠道暂停、输入限额、客户版本冲突与权限、可操作页面和生产构建。只运行本地合成咨询数据，实际 Facebook 验证继续后置。

回滚：停止本项目服务并回退代码提交；已应用迁移和持久事件保留，数据库结构回退通过后续迁移完成。

实施检查点：新增 2 项合同、17 项隔离数据库和 2 项浏览器流程；全部回归共 246 项测试，9 类检查通过，源码摘要 `72d4316ed196417b5b4eb93961dc915658bd24f839d03765bdededf014ea5047`。包括真实子进程提交前/后终止、等待数据库锁后重新核对会话期限、断线后原消息重试、同名访客/跨品牌隔离、客服窗口与退出、负责人/备注/阶段以及手机尺寸页面。

生产构建在独立本地端口验证访客页面、独立 Cookie、持久消息确认和去重、客户建档来源、跟进备注及入口暂停。没有真实客户或 Facebook 请求。人工发送、接管与完整站内接待仍待实现，完整交付和关机条件未满足。
